Credentials Guide

Where to get each API key Open-Dispatch reads, and what to paste into .env.

Only configure the platforms you actually use. Missing variables are silently skipped — the API only complains when a dispatch targets a platform whose credentials aren't set. You can add more later.

Before you start

  1. Copy the template and edit it: cp .env.example .env
  2. Fill in the variables for the platforms you want below.
  3. Restart the server — credentials are read at request time, not at boot.
  4. Confirm the platform shows as configured in the dashboard, then dispatch a test post.

Multiple accounts on one platform. Append an uppercase suffix to the variable, then target it with platform:suffix. Personal and work: TWITTER_ACCESS_TOKEN_PERSONAL and TWITTER_ACCESS_TOKEN_WORK, then {"targets": ["twitter:work"]}. The unsuffixed variable is the default account.

Twitter / X

  1. Go to developer.x.com and sign in.
  2. Open the Developer Portal and create a Project, then an App.
  3. Copy API Key → TWITTER_API_KEY and API Key Secret → TWITTER_API_SECRET.
  4. Scroll to Keys and Tokens, generate an Access Token and Secret, and copy both.

You need the Access Token and Secret (the app's own token), not the Bearer Token — this adapter posts as the app.

Recent X API pricing is per-post and paid at volume. Check the current tier before building on it.

Bluesky

The simplest one — no developer account or app registration needed.

  1. Sign in at bsky.app.
  2. Settings → App Passwords → Create App Password. Name it something like open-dispatch.
  3. Copy the generated password → BLUESKY_APP_PASSWORD.
  4. BLUESKY_HANDLE is your handle without the @, e.g. you.bsky.social.

Use an app password, never your main account password. App passwords can be revoked individually without locking you out.

Telegram

  1. Message @BotFather and send /newbot.
  2. Follow the prompts to name your bot. Copy the token it gives you → TELEGRAM_BOT_TOKEN.
  3. Add the bot to your target channel, then send it a message (bots cannot read channel messages they weren't sent).
  4. Get the chat ID: message the bot, then open https://api.telegram.org/bot<YOUR_TOKEN>/getUpdates in a browser and read chat.id.

TELEGRAM_CHAT_ID accepts a numeric ID or @channelusername for public channels.

The bot token grants full control of the bot. Anyone with it can post as the bot — treat it like a password.

Instagram

Requires a Facebook app and a professional (Business or Creator) Instagram account.

  1. Convert your Instagram account to Business or Creator if it isn't already — personal accounts can't use the API.
  2. Go to developers.facebook.com → My Apps → Create App.
  3. Add the Instagram Graph API product, then connect your Instagram account.
  4. Generate a token with the instagram_basic and instagram_content_publish permissions → IG_TOKEN.
  5. IG_USER_ID is the numeric IG user id. Open https://graph.facebook.com/v21.0/me/accounts?fields=id,username&access_token=<TOKEN> and find the account.

Instagram requires a publicly reachable image/video URL — it fetches the media itself and cannot accept raw bytes. A localhost path will not work. Host your media somewhere publicly readable.

LinkedIn

  1. Go to linkedin.com/developers/apps → Create app.
  2. Under Products, add w_member_social for personal posts, or w_organization_social for company pages.
  3. In Auth → Access Token, generate a token with that permission → LINKEDIN_ACCESS_TOKEN.
  4. LINKEDIN_AUTHOR_URN identifies who posts. Open https://api.linkedin.com/v2/userinfo with your token and read the sub field, then build:
# person
urn:li:person:<sub from userinfo>
# organization
urn:li:organization:<numeric org id>

Access tokens are short-lived and the OAuth review process can take days. Don't plan around a token you cannot renew.

Threads

  1. Same Meta developer app as Instagram, but add the Threads API product.
  2. Create a long-lived token with the threads_basic and threads_content_publish scopes → THREADS_ACCESS_TOKEN.
  3. THREADS_USER_ID is your Threads user id, found at https://graph.threads.net/v1.0/me?fields=id,username&access_token=<TOKEN>.

Optional: THREADS_SETTLE_SECONDS (default 30, max 120) — how long to wait after creating a container before publishing. Meta recommends a short delay so their pipeline can ingest the media. A value that isn't a number falls back to the default.

YouTube Shorts

Three values, all from one OAuth client. The refresh token is the important one — it is what lets Open-Dispatch get new access tokens without you.

  1. Go to console.cloud.google.com and create a project.
  2. APIs & Services → Library → enable the YouTube Data API v3.
  3. APIs & Services → Credentials → Create Credentials → OAuth client ID → type Desktop app → note the Client ID and Client Secret.
  4. Authorise with the https://www.googleapis.com/auth/youtube.upload scope and a redirect_uri of http://localhost.
  5. From the redirect URL's code parameter, exchange it for a refresh token:
curl -X POST https://oauth2.googleapis.com/token \\
  -d "client_id=<CLIENT_ID>" \\
  -d "client_secret=<CLIENT_SECRET>" \\
  -d "code=<CODE_FROM_REDIRECT>" \\
  -d "grant_type=authorization_code" \\
  -d "redirect_uri=http://localhost"

Copy refresh_token from the response. Set youtube_privacy to public, unlisted, or private in your dispatch payload — anything else is rejected rather than silently publishing publicly.

TikTok

  1. Go to developers.tiktok.com and create an app.
  2. Add the Content Posting API product.
  3. Generate an access token with the video.publish scope → TIKTOK_ACCESS_TOKEN.

Requires the app to pass TikTok's review before posting to public accounts. Optional: TIKTOK_PRIVACY_LEVEL (default PUBLIC_TO_EVERYONE).

TikTok fetches the video from a URL you supply, so the URL must be publicly reachable — the same constraint as Instagram.

Facebook

  1. developers.facebook.com → your app → Use cases → Facebook Login for Business (or a Pages use case).
  2. Add the Pages product and request pages_manage_posts.
  3. Generate a Page access token — this is not an app token, it must be scoped to the page.
  4. FACEBOOK_ACCESS_TOKEN is that page token; FACEBOOK_PAGE_ID is the numeric page id.

Find both at https://graph.facebook.com/v21.0/me/accounts?fields=id,name,access_token&access_token=<USER_TOKEN>.

Discord

No bot token or OAuth — a webhook URL is the whole integration.

  1. In Discord: Server Settings → Integrations → Webhooks → New Webhook.
  2. Choose a channel and name it, then Copy Webhook URL → DISCORD_WEBHOOK_URL.

Anyone with that URL can post to the channel. Treat it as a secret — don't paste it into a public issue or a screenshot.

Troubleshooting

"TELEGRAM_BOT_TOKEN / TELEGRAM_CHAT_ID missing"

One of the two is unset for that target. If you used telegram:work, the variable needs the _WORK suffix: TELEGRAM_CHAT_ID_WORK.

A 401 or auth: error

Credentials are being rejected. A revoked token and a wrong one look identical. Re-copy them, and confirm the account still has posting permission in the platform's UI — deleting an app or revoking a session invalidates the token even though it still looks complete.

Instagram/TikTok: media fetch fails

The platform downloads your media from a URL you gave it. A localhost or private address is invisible to them. Use a publicly reachable HTTPS URL.

LinkedIn: 403 insufficient scope

The token lacks the product you need. w_member_social posts to a profile; w_organization_social posts to a company page. Also confirm LINKEDIN_AUTHOR_URN matches the token's type — a person token with an organization URN is rejected.

Posts appear duplicated

Only possible if a failure happened mid-sequence — e.g. a 5-item Twitter thread where the third failed. Cancel the campaign, then check the dashboard for the rows that already published.

Security notes

  • Your credentials never leave your machine. Open-Dispatch has no telemetry and no cloud component.
  • Credentials in .env and profiles.json are plaintext. Protect the data directory; Open-Dispatch sets 0600/0700 where it can, but on a shared host also check ownership yourself.
  • Never paste a secret into a GitHub issue, a screenshot, or a log you intend to share. If you do, rotate it.
  • Prefer the dashboard's Profiles page over .env when you run several accounts — it keeps them in one place with per-field removal.
